# Build Together v3 — Tilly

Tilly v3 is the same couples-finance app (Plaid, passkeys, three-tier memory, Expo + Express + Drizzle) with a real coach home, money habits, and a first recurring-spend detector.

The product name in the app stays **Tilly**. The app version is **3.0.0**.

## What shipped

### Coach Home

`GET /api/tilly/today` now includes a `coach` object:

- `briefing` — a short note grounded in the dossier money arc, this week's spend, the next bill, and an open habit
- `cash` — liquid balance (Plaid `accountsGet`, cached 12h on `cash_positions`) or the self-reported snapshot
- `upcoming` — bills in the next 14 days plus standing payday sweeps
- `habits` — streak strip
- `primaryAction` — one next step (clear pending, check in, look at a bill, or start a habit)

The Today screen renders that strip. Spend (`GET /api/tilly/spend-pattern`) returns `ready: true` with an empty week when there is nothing to total, instead of a phase stub.

### Money habits

Tables: `money_habits`, `habit_checkins`.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/habits` | Habits with streak + weekly completion, plus Tilly's suggestions |
| POST | `/api/habits` | Create one (`source: "tilly"` when accepting a suggestion) |
| POST | `/api/habits/:id/checkin` | Check in for today (or a `date`) |
| POST | `/api/habits/:id/archive` | Retire it |

Kinds: `no_spend_day`, `save_amount`, `review_pending`, `gratitude_spend`, `weekly_checkin`, `custom`.

Chat tools: `createHabit`, `checkInHabit`. Suggestions come from observed restaurant-day clustering, subscription count, and the pending queue. Check-ins, suggestions, and digest outcomes are L1 events (`habit_checkin`, `habit_suggested`, `coach_digest_sent`, `automation_nudge`) so the nightly distiller can turn them into L2 memories.

Open Habits from the streak strip on Today.

### Recurring spend v1

`scanSubscriptions` always reads stored `plaid_transactions` (accepted and pending review, last ~400 days) and keeps a merchant only when the amount is stable and the gap matches a weekly, biweekly, monthly, quarterly, or yearly cadence. Two coffees do not qualify. Transfers, income, fees, loans, and taxes are skipped.

Plaid `transactionsRecurringGet` still runs on `POST /api/subscriptions/scan` when credentials exist. The morning cron runs the history path only, so a slow institution cannot eat the function budget.

### Coach automation

`GET` or `POST /api/cron/coach-digest` (Bearer `CRON_SECRET`, same as the other cron routes).

Vercel schedule: `15 * * * *` (hourly). Each user is processed once during their local 08:00–10:59 window. The in-process scheduler also fires it at 12:15 UTC, which is morning in Toronto.

Priority for the one note: broken daily habit, bill inside 3 days, pending pile of 5+, otherwise a morning line (including a habit suggestion when they have none). Quiet hours skip the push but still record the digest. `?force=1` ignores the hour window for a manual run.

### Pending review

`shouldAutoAcceptByAI` now files ordinary spend when Tilly is confident and the amount is under the existing cap: safe Plaid personal-finance categories at ≥ 0.8, or a real spend category from the classifier at ≥ 0.85. Loans, transfers, and ambiguous categories stay in the queue. Merchant rules are unchanged and still win.

### Demo routes

`POST /api/demo/seed` and `/api/demo/clear` mount only when both `NODE_ENV` and `VERCEL_ENV` are not `production`. `mountDemoRoutes` also refuses to register in production if something calls it directly. The Spend "try with demo data" control is `__DEV__` only.

## Try it locally

```bash
pnpm install
# api-server env: DATABASE_URL, and the admin/session secrets the server
# already requires. Plaid keys are optional — habits, empty Spend, and
# history-based subscription detection work without them.
pnpm --filter @workspace/api-server run dev
pnpm --filter @workspace/buildtogether run dev
```

1. Sign in and finish onboarding so the account has a household.
2. Today shows the briefing, cash line, bills, habit strip, and one action.
3. Open Habits, start "No-spend day", check in. Today’s strip updates.
4. With accepted transactions on a steady cadence, `POST /api/subscriptions/scan` fills Subscriptions. The next morning cron does the history pass on its own.
5. Chat can say "start a weekly money check-in" (`createHabit`) or "no-spend day done" (`checkInHabit`). The same turn sees the Today block in its system context.

Manual digest (dev, `CRON_SECRET` unset is allowed outside production):

```bash
curl -X POST "http://localhost:<port>/api/cron/coach-digest?force=1"
```

## Schema

Applied on boot by `server/migrate-boot.ts` (`CREATE TABLE IF NOT EXISTS`):

- `money_habits`
- `habit_checkins` (unique habit + date)
- `coach_digests` (unique user + local date + kind)
- `cash_positions`

Account deletion purges those tables with the rest of the household.
